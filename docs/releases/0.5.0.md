# 0.5.0 release scope

## 中文

状态：发布候选，尚不表示 crates.io 已发布。正式可用性以
[GitHub Releases](https://github.com/calcit-lang/calx-vm/releases) 和 crates.io 为准。
关联 [#60](https://github.com/calcit-lang/calx-vm/issues/60)、
[#61](https://github.com/calcit-lang/calx-vm/issues/61)。

### 范围与兼容性

0.5.0 汇集已经合并的三项改动：有界运行时 trace（#58）、strict 值域封闭（#62）与
尾调用 locals 容量复用（#63）。strict 对部分 0.4.0 曾接受的程序改变准入行为，因此采用
0.5.0 作为 0.x 的显式兼容边界；不是新的 VM profile，也不表示整份 0.5 roadmap 已完成。

- strict 不接受 `Nil`、`Dynamic`、没有元素类型证明的 `List` 或 `Link`；不可达代码也须遵守。
- void 使用零结果与 `CalxRunResult::Void`，未初始化槽使用独立 `Uninitialized`；不借用 nil。
- `F64Buffer` 保持 immutable typed entry/import、显式所有权与 checked conversion/bounds；
  globals/constants 仍不接受 buffer。scalar/buffer ABI edition 不因本次发布改变。
- 尾调在同一 frame 内复用 locals capacity，保留旧引用释放、trap、source span 与 trace 语义。
  无全局 pool、公共复用 API、unsafe 扩张、Dynamic fallback 或运行失败后重跑 Calcit。
- 异质程序仍走显式 legacy 路径，不能将其验证视为 strict 证明。详见
  [strict 迁移指南](../strict-value-domain.md)与[运行时 trace](../tutorials/runtime-trace.md)。

### 证据与发布顺序

[独立 benchmark 摘要](https://github.com/calcit-lang/calcit-calx-bench/blob/e1f7a9ae2320d42af5228127c57f7c9b67d45fb0/benchmarks/calx/20260906-tail-call-comparison.md)
记录固定源码的父提交/合并提交对照。它是未发布 revision 的同机微基准；本仓库不复制 raw
JSON，不将其中收益表述为 0.5.0 已发布消费者的端到端性能，也不增加机器耗时门禁。

1. 发布 PR 通过 fmt、debug/release tests、全部 `try.sh` demos、严格 Clippy 与 package verification，
   完成最新 head review、清零有效意见，CI 全绿且 CLEAN 后合并。
2. 拉取精确 main HEAD，确认该 SHA 的 required Actions 成功；annotated `0.5.0` tag 必须指向
   同一 SHA，GitHub Release 触发既有 publish workflow。
3. 确认 publish workflow 成功且 crates.io 可读到 0.5.0，消费者才升级正式依赖。
4. Calcit 使用精确版本 `=0.5.0` 并验证 lowering/correctness；harness 随后固定已验证的
   Calcit revision、版本/adapter identity，运行完整门禁。实验 path override 不成为正式依赖。

没有发布或消费者验证成功时不关闭 #60；native `calcit-calx` 模块的发布仍是独立生态任务。

## English

Status: release candidate, not a claim of crates.io availability. GitHub Releases
and crates.io are authoritative. Tracks #60 and #61.

Version 0.5.0 groups merged bounded runtime tracing (#58), closed strict admission
(#62), and tail-call locals reuse (#63). Some programs accepted under 0.4.0 are now
rejected in strict mode, so 0.5.0 marks an explicit 0.x compatibility boundary.
It introduces neither another VM profile nor completion of every roadmap candidate.

Strict excludes Nil, Dynamic, untyped Lists and Link, including unreachable code.
Void and Uninitialized remain explicit. Immutable F64Buffer ownership and typed
entry/import boundaries retain conversion/bounds checks; buffer globals/constants
remain rejected. Scalar/buffer ABI editions are unchanged. Tail calls reuse locals
capacity in one frame while preserving reference release, traps, source spans and
tracing. No global pool, public reuse API, expanded unsafe, Dynamic fallback or
Calcit retry after runtime failure is introduced. Legacy heterogeneous programs
remain explicit and supply no strict proof. See the linked migration/trace guides.

The linked standalone evidence compares unreleased revisions on one machine. Raw
JSON stays outside this repository. Do not equate its microbenchmark gains with
published 0.5.0 consumer end-to-end gains or machine-specific correctness gates.

Release order: pass formatting, debug/release tests, all demos, strict Clippy and
package verification; finish latest-head review and resolve valid findings before
merging with green CI/CLEAN status. Verify required Actions on exact main, point an
annotated 0.5.0 tag at that same SHA, then create the GitHub Release. The existing
publish workflow must succeed and crates.io must expose 0.5.0 before consumers
upgrade. Calcit then adopts exact `=0.5.0` and verifies lowering/correctness; the
harness pins the verified Calcit revision, version/adapter identity and passes its
full gates. Experimental path overrides are not formal dependencies. Keep #60 open
until publication and consumer verification; native calcit-calx releases remain separate.
