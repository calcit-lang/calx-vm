### 范围与兼容性

0.5.0 汇集已经合并的三项改动：有界运行时 trace（[PR #58](https://github.com/calcit-lang/calx-vm/pull/58)）、
strict 值域封闭（[Issue #59](https://github.com/calcit-lang/calx-vm/issues/59)，
[PR #62](https://github.com/calcit-lang/calx-vm/pull/62)）与尾调用 locals 容量复用
（[Issue #60](https://github.com/calcit-lang/calx-vm/issues/60)，
[PR #63](https://github.com/calcit-lang/calx-vm/pull/63)）。strict 对部分 0.4.0 曾接受的程序改变准入行为，因此采用
0.5.0 作为 0.x 的显式兼容边界；不是新的 VM profile，也不表示整份 0.5 roadmap 已完成。

- strict 不接受 `Nil`、`Dynamic`、任何 `List` 值或 `Link`；当前 List 没有元素类型合同，
  空列表与同质列表也不例外。不可达代码同样须遵守。
- void 使用零结果与 `CalxRunResult::Void`，未初始化槽使用独立 `Uninitialized`；不借用 nil。
- `F64Buffer` 保持 immutable typed entry/import、显式所有权与 checked conversion/bounds；
  globals/constants 仍不接受 buffer。scalar/buffer ABI edition 不因本次发布改变。
- 尾调在同一 frame 内复用 locals capacity，保留旧引用释放、trap、source span 与 trace 语义。
  无全局 pool、公共复用 API、unsafe 扩张、Dynamic fallback 或运行失败后重跑 Calcit。
- 异质程序仍走显式 legacy 路径，不能将其验证视为 strict 证明。详见
  [strict 迁移指南](../strict-value-domain.md)与[运行时 trace](../tutorials/runtime-trace.md)。

## English

Status: published. The [GitHub Release](https://github.com/calcit-lang/calx-vm/releases/tag/0.5.0)
and crates.io are authoritative. The annotated tag, exact-main Test, and successful
[publish workflow](https://github.com/calcit-lang/calx-vm/actions/runs/34005734004) identify commit
`768146978bb750cb7385ce28896588159c99d377`. Tracks #60 and #61.

Version 0.5.0 groups merged bounded runtime tracing
([PR #58](https://github.com/calcit-lang/calx-vm/pull/58)), closed strict admission
([Issue #59](https://github.com/calcit-lang/calx-vm/issues/59),
[PR #62](https://github.com/calcit-lang/calx-vm/pull/62)), and tail-call locals reuse
([Issue #60](https://github.com/calcit-lang/calx-vm/issues/60),
[PR #63](https://github.com/calcit-lang/calx-vm/pull/63)). Some programs accepted under 0.4.0 are now
rejected in strict mode, so 0.5.0 marks an explicit 0.x compatibility boundary.
It introduces neither another VM profile nor completion of every roadmap candidate.

Strict excludes Nil, Dynamic, all List values and Link, including unreachable code.
The current List type has no element-type contract; empty or homogeneous lists are
not exceptions.
Void and Uninitialized remain explicit. Immutable F64Buffer ownership and typed
entry/import boundaries retain conversion/bounds checks; buffer globals/constants
remain rejected. Scalar/buffer ABI editions are unchanged. Tail calls reuse locals
capacity in one frame while preserving reference release, traps, source spans and
tracing. No global pool, public reuse API, expanded unsafe, Dynamic fallback or
Calcit retry after runtime failure is introduced. Legacy heterogeneous programs
remain explicit and supply no strict proof. See the linked migration/trace guides.

The linked standalone evidence compares unreleased revisions on one machine. Raw
JSON stays outside this repository. Do not equate its microbenchmark gains with
published 0.5.0 consumer end-to-end gains or machine-specific correctness gates.

Release verification: formatting, debug/release tests, all demos, strict Clippy,
package verification, latest-head review, and required CI passed before release.
The annotated tag, exact-main Test, and GitHub Release use the same commit recorded
above. The publish workflow succeeded and crates.io exposes 0.5.0. The exact-version
Calcit and harness consumer chain passed its complete gates, so #60 is closed.
Experimental path overrides are not formal dependencies; native calcit-calx releases
remain separate.
