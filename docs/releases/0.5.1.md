# 0.5.1 release scope / 0.5.1 发布范围

## English

Status: published. The [GitHub Release](https://github.com/calcit-lang/calx-vm/releases/tag/0.5.1)
and crates.io are authoritative for availability. The annotated tag, exact-main Test, and successful
[publish workflow](https://github.com/calcit-lang/calx-vm/actions/runs/34424152625) identify commit
`f5a2c64771ea685208403c058c75f1667294a217`. This patch release tracks
[#70](https://github.com/calcit-lang/calx-vm/issues/70) and contains the named
strict-entry implementation merged in
[#71](https://github.com/calcit-lang/calx-vm/pull/71).

### Scope and compatibility

- A validated strict program may omit a synthetic `main` and execute an exact
  function through `run_typed_entry` or `run_traced_entry`.
- Entry lookup never falls back. Arguments and the embedding result arity are
  checked before execution; the result boundary continues to support zero or
  one value.
- Named and `main` compatibility APIs share state reset and the interpreter
  loop. Traced execution keeps the same observer and event-limit behavior.
- Existing `run_typed` and `run_traced` callers remain compatible. Legacy
  dynamic VMs cannot use the named strict APIs.
- This release adds no VM value, opcode, Dynamic/Nil fallback, scheduler,
  export registry, platform FFI, or dependency.

### Release verification

1. Formatting, debug/release tests, all demos, strict Clippy, packaging,
   latest-head review, and required CI passed before the release.
2. The annotated `0.5.1` tag, exact-main Test, and GitHub Release use the same commit recorded above.
3. The publish workflow succeeded and crates.io exposes 0.5.1.
4. Calcit adopted the exact `calx_vm = "=0.5.1"` dependency; its consumer gates and first checked
   lifecycle-program lowering slice passed before #70 closed.

### 范围与兼容性

- validated strict program 可以不合成 `main`，通过 `run_typed_entry` 或
  `run_traced_entry` 按准确函数名执行。
- 入口查找不做回退；参数与 embedding 返回值数量在执行前检查，返回边界继续只支持零或一个值。
- 具名 API 与 `main` 兼容 API 共享状态 reset 和 interpreter loop；trace 继续保持 observer 与
  event limit 语义。
- 现有 `run_typed` 与 `run_traced` 调用保持兼容；legacy dynamic VM 不能调用具名 strict API。
- 本版本不新增 VM value、opcode、Dynamic/Nil fallback、scheduler、export registry、平台 FFI 或依赖。
